# MCP Server 操作規範

此文件定義 SAP B1 SQL MCP Server 的操作協作模式和使用規範。

## 操作模式定義

### 模式 1：直接執行 (Direct Execution)

**適用於：** 純讀取操作

**行為：**
- 收到要求後直接執行
- 不需要事前確認
- 立即返回結果

**適用工具：**
- `sql_query` - SELECT 查詢
- `get_table_info` - 取得資料表結構
- `list_tables` - 列出所有資料表
- `list_backups` - 列出備份檔案
- `get_db_status` - 查看資料庫狀態

**範例對話：**

```
用戶：幫我查詢 OITM 資料表的前 10 筆資料
AI：[直接使用 sql_query 工具執行]
    查詢結果：[顯示 10 筆資料]
```

---

### 模式 2：顯示 SQL 並確認 (Confirm with SQL)

**適用於：** 所有可能修改資料的操作

**行為：**
1. 分析用戶需求
2. **生成完整的 SQL 語句**
3. **明確顯示 SQL 給用戶檢視**
4. **等待用戶明確確認**（「確認」、「執行」、「OK」等）
5. 確認後才執行操作
6. 返回執行結果

**適用工具：**
- `sql_write` - INSERT/UPDATE/DELETE

**適用操作類型：**
- INSERT - 新增資料
- UPDATE - 修改資料
- DELETE - 刪除資料
- CREATE - 建立物件
- ALTER - 修改結構
- DROP - 刪除物件
- MERGE - 合併資料

**範例對話：**

```
用戶：幫我在 TestTable 新增一筆資料，Name='測試', Value=100

AI：我將執行以下 SQL 語句：

    INSERT INTO TestTable (Name, Value)
    VALUES ('測試', 100)

    這個操作將會：
    - 在 TestTable 新增 1 筆記錄
    - 寫入前會自動建立備份

    請確認是否執行？

用戶：確認

AI：[執行 sql_write 工具]
    執行成功，已新增 1 筆記錄
    備份已建立：rolling_20250430_100523.bak
```

**重要：** AI 必須在執行前明確顯示完整 SQL，不可省略此步驟！

---

### 模式 3：顯示操作並確認 (Confirm without SQL)

**適用於：** 關鍵操作（不需要看到技術細節）

**行為：**
1. 分析用戶需求
2. **描述將要執行的操作**（不顯示完整 SQL）
3. **說明操作的影響和風險**
4. **等待用戶明確確認**
5. 確認後才執行
6. 返回執行結果

**適用工具：**
- `restore_backup` - 還原資料庫
- `create_backup` - 手動建立備份

**範例對話：**

```
用戶：幫我還原到昨天的備份

AI：我找到以下備份檔案：
    - daily_20250429.bak (昨天，50.2 MB)

    還原操作將會：
    1. 關閉所有現有連線
    2. 將資料庫還原到 2025-04-29 的狀態
    3. 當前的所有變更將會遺失
    4. 預計需要 1-2 分鐘

    ⚠️ 警告：此操作無法復原！

    請確認是否執行？

用戶：確認

AI：[執行 restore_backup 工具]
    還原完成，資料庫已回復到 2025-04-29 的狀態
```

| `create_backup` | 模式 3（顯示操作並確認） | 手動備份 |

## 操作規則

### 1. 讀取操作（模式 1）

**規則：** 直接執行，不需確認

**判斷標準：**
- 只讀取資料，不修改任何內容
- 不影響資料庫狀態
- 可以重複執行而沒有副作用

**關鍵字：**
- SELECT
- 查詢、讀取、檢視、列出、顯示
- 取得、獲取、查看

**AI 行為：**
```
用戶請求 → 直接執行 → 返回結果
```

---

### 2. 寫入操作（模式 2）

**規則：** 必須顯示完整 SQL 並獲得確認

**判斷標準：**
- 會修改、新增或刪除資料
- 會改變資料庫結構
- 執行後無法輕易復原

**關鍵字：**
- INSERT, UPDATE, DELETE
- CREATE, ALTER, DROP
- MERGE, TRUNCATE
- 新增、修改、刪除、變更
- 寫入、更新

**AI 行為：**
```
用戶請求 → 生成 SQL → 顯示 SQL → 等待確認 → 執行 → 返回結果
```

**AI 必須做到：**
1. ✅ 明確顯示完整 SQL 語句
2. ✅ 說明操作會影響多少筆資料
3. ✅ 提示會自動建立備份
4. ✅ 等待用戶明確確認（「確認」、「執行」、「OK」、「是」等）
5. ❌ 絕不可以在未確認前執行

---

### 3. 關鍵操作（模式 3）

**規則：** 顯示操作描述並獲得確認

**判斷標準：**
- 對整個資料庫有重大影響
- 執行後難以復原或無法復原
- 需要較長時間執行

**關鍵字：**
- BACKUP, RESTORE
- 備份、還原、恢復

**AI 行為：**
```
用戶請求 → 分析影響 → 說明操作 → 警告風險 → 等待確認 → 執行 → 返回結果
```

**AI 必須做到：**
1. ✅ 清楚說明將要執行的操作
2. ✅ 列出操作的影響範圍
3. ✅ 明確警告風險（如資料遺失）
4. ✅ 等待用戶明確確認
5. ❌ 絕不可以在未確認前執行

---

## 確認方式

### 用戶確認的有效表達

以下表達視為「確認」：
- ✅ 確認
- ✅ 執行
- ✅ OK / ok
- ✅ 是 / Yes
- ✅ 繼續
- ✅ 沒問題
- ✅ 可以

以下表達視為「取消」：
- ❌ 取消
- ❌ 不要
- ❌ No / 否
- ❌ 停止
- ❌ 等等
- ❌ 先不要

### 模糊或不明確的回應

如果用戶的回應不明確，AI 應該：
1. 再次詢問確認
2. 提供「確認」或「取消」的選項
3. 不要自行判斷並執行

## 特殊情況處理

### 1. 批量操作

如果操作會影響多筆資料（超過 10 筆），AI 應該：
1. 額外強調影響範圍
2. 建議先查詢受影響的資料讓用戶確認
3. 提供分批執行的選項

**範例：**

```
用戶：刪除 2024 年以前的所有訂單

AI：這個操作可能會影響大量資料。讓我先查詢一下...

    [執行 SELECT COUNT(*)]

    查詢結果：共有 1,523 筆符合條件的記錄

    我將執行：
    DELETE FROM Orders
    WHERE OrderDate < '2024-01-01'

    ⚠️ 警告：
    - 將刪除 1,523 筆訂單記錄
    - 此操作無法復原（但會先自動備份）
    - 建議先匯出這些資料

    您確定要執行嗎？
```

### 2. 危險操作

對於特別危險的操作（如 DROP、TRUNCATE），AI 應該：
1. 雙重確認
2. 明確說明後果
3. 建議替代方案

**範例：**

```
用戶：刪除 TestTable 資料表

AI：⚠️ 這是一個危險操作！

    您要求刪除整個 TestTable 資料表，這將：
    1. 永久刪除資料表結構
    2. 永久刪除所有資料
    3. 可能影響其他相依的物件

    SQL 語句：
    DROP TABLE TestTable

    建議：
    - 如果只是要清空資料，使用 DELETE 而不是 DROP
    - 如果確定要刪除，建議先手動備份

    如果您確定要執行此危險操作，請輸入「確認刪除」
```

### 3. 連續操作

如果用戶要求執行多個寫入操作，每個操作都需要單獨確認：

**範例：**

```
用戶：幫我新增 3 筆測試資料到 TestTable

AI：我將分別新增 3 筆資料。

    === 第 1 筆 ===
    INSERT INTO TestTable (Name, Value) VALUES ('Test1', 100)

    請確認是否執行第 1 筆？

用戶：確認

AI：[執行第 1 筆]
    成功新增 1 筆記錄

    === 第 2 筆 ===
    INSERT INTO TestTable (Name, Value) VALUES ('Test2', 200)

    請確認是否執行第 2 筆？

...
```

## AI 助手應遵循的原則

### 1. 安全第一
- 永遠優先考慮資料安全
- 對於任何寫入操作，寧願多確認一次也不要冒險

### 2. 透明原則
- 清楚說明將要執行的操作
- 不隱藏技術細節（對於模式 2）
- 誠實報告可能的風險

### 3. 用戶控制
- 將決定權交給用戶
- 不要自作主張
- 尊重用戶的取消請求

### 4. 友善提示
- 提供有用的建議
- 警告潛在問題
- 提供替代方案

### 5. 記錄追蹤
- 所有操作都有日誌記錄
- 告知用戶備份的建立
- 提供還原的方式

## 配置自訂

用戶可以在 `config.json` 中自訂操作模式：

```json
{
  "operation_modes": {
    "tool_mode_mapping": {
      "sql_query": "direct",           // 可改為 "confirm_with_sql"
      "sql_write": "confirm_with_sql",  // 可改為 "direct"（不建議）
      ...
    }
  }
}
```

但我們**強烈不建議**將寫入操作改為「直接執行」模式。

## 總結

**記住：**
- 📖 **讀取操作** = 直接執行
- ✍️ **寫入操作** = 顯示 SQL + 確認
- ⚠️ **關鍵操作** = 說明風險 + 確認

**AI 的黃金規則：**
> 當不確定時，選擇更安全的方式 — 詢問用戶確認！
