# 工作流程規範 (Workflow Standards)

**版本**：2.0
**更新日期**：2025-11-14

---

## Shopfloor 協作模式

本規範採用 **Shopfloor 協作模式**，目的是優化 Claude 與使用者的協作效率。

---

## 核心原則

### 1. 檔案輸出規範

**所有程式碼產出必須先輸出到 `shopfloor/Claude_TMP/`**

#### 目錄結構

**預設結構**：
```
shopfloor/Claude_TMP/
├── sql/            # SQL 腳本（建表、查詢、修改）
├── code/           # 程式碼檔案
└── etc/            # 其他檔案（配置、文件）
```

**可自訂結構範例**：

依語言分類：
```
shopfloor/Claude_TMP/
├── python/
├── javascript/
├── sql/
└── etc/
```

依功能分類：
```
shopfloor/Claude_TMP/
├── api/
├── models/
├── tests/
├── migrations/
└── etc/
```

依日期分類：
```
shopfloor/Claude_TMP/
├── 2025-11-14/
├── 2025-11-15/
└── archive/
```

> **注意**：目錄結構可根據專案需求調整，只需在 `SESSION_INIT.md` 中說明即可

---

#### 檔案命名規範

**1. SQL 腳本**
```
格式：[編號]_[用途]_[物件名稱].sql

範例：
- 01_create_table_users.sql
- 02_alter_table_add_email.sql
- 03_query_active_users.sql
```

**2. 程式碼完整檔案**
```
格式：直接使用模組名稱或類別名稱

Python 範例：
- user_service.py
- auth_middleware.py
- database.py

JavaScript 範例：
- userService.js
- authMiddleware.js
- database.js

其他語言依照該語言的命名慣例
```

**3. 部分代碼片段（TXT）**
```
格式：[目標檔案]_[用途].txt

範例：
- main_add_routes.txt       # 要加到 main 的路由
- config_add_settings.txt   # 要加到 config 的設定
- utils_new_functions.txt   # 要加到 utils 的新函式
```

**4. 配置檔案**
```
格式：[用途]_config.[副檔名]

範例：
- database_config.json
- api_settings.yaml
- logging_config.toml
- environment.env
```

---

### 2. 程式碼顯示規範

**不在對話中貼大段程式碼**

#### 規則

- ❌ **禁止**：在對話中貼超過 **20 行**的程式碼
- ✅ **允許**：簡短的程式碼片段（少於 10 行）用於說明
- ✅ **允許**：錯誤訊息和 Log 輸出
- ✅ **允許**：單行指令和範例

#### 正確做法

**❌ 錯誤範例**：
```
你：請建立使用者 API

Claude：好的，以下是完整程式碼：

[貼上 100 行 Python 程式碼]
[貼上 50 行 SQL]
[貼上 30 行配置]

請將這些程式碼加入你的專案...
```

**✅ 正確範例**：
```
你：請建立使用者 API

Claude：📁 已產生檔案到 shopfloor/Claude_TMP/：

SQL 腳本（1 個）：
1. sql/01_create_users_table.sql - 建立使用者資料表

Python 檔案（3 個）：
1. code/user_model.py - SQLAlchemy 資料模型
2. code/user_schema.py - Pydantic 驗證綱要
3. code/user_router.py - FastAPI 路由

📋 使用順序：
1. 執行 SQL 腳本建立資料表
2. 將 Python 檔案加入對應目錄
3. 在 main.py 註冊路由

請執行後回報結果。
```

#### 優點

- 節省 Token（不在對話中顯示大量代碼）
- 減少對話視覺疲勞
- 方便使用者直接使用（複製貼上）
- 保留完整歷史（所有產出都有檔案記錄）
- 易於版本控制（可 git add 這些檔案）
- IDE 支援（語法高亮、程式碼提示）

### 3. 檔案說明規範

**每個輸出檔案開頭必須加上使用說明**

#### 完整檔案格式

**Python 範例**：
```python
"""
=====================================================================
  user_model.py - 使用者資料模型
=====================================================================
更新時間：2025-11-14

一、用途說明
---------------------------------------------------------------------
SQLAlchemy 使用者資料模型，定義 users 資料表結構

二、目標位置
---------------------------------------------------------------------
應加入到：app/models/user.py
位置：models 目錄下作為獨立模組

三、使用方式
---------------------------------------------------------------------
1. 將此檔案複製到 app/models/ 目錄
2. 在 __init__.py 中 import: from .user import User
3. 執行 alembic 遷移建立資料表

四、需要檢查的點
---------------------------------------------------------------------
- [ ] 檢查資料庫連線字串
- [ ] 確認 SQLAlchemy 版本
- [ ] 調整欄位長度符合需求
- [ ] 檢查索引設定

五、相依套件
---------------------------------------------------------------------
- sqlalchemy >= 2.0
- python >= 3.10

=====================================================================
"""

# 實際程式碼開始
from sqlalchemy import Column, Integer, String
# ...
```

**JavaScript 範例**：
```javascript
/**
```

#### 部分代碼 TXT 格式

```
=====================================================================
  main_add_routes.txt - 新增路由到 main.py
=====================================================================
更新時間：2025-11-14

一、用途說明
---------------------------------------------------------------------
將使用者相關路由註冊到 FastAPI 應用程式

二、目標位置
---------------------------------------------------------------------
應加入到：app/main.py
位置：在現有的 app.include_router(...) 區塊後面

三、使用方式
---------------------------------------------------------------------
1. 開啟 app/main.py
2. 找到路由註冊區塊（通常在 # Routers 註解後）
3. 將以下程式碼加入該區塊

四、需要檢查的點
---------------------------------------------------------------------
- [ ] 確認 user_router 已正確 import
- [ ] 檢查路由前綴是否符合 API 版本規範
- [ ] 確認沒有路由衝突

五、完整代碼
---------------------------------------------------------------------
# Import（加在檔案開頭的 import 區塊）
from app.api.v1 import user_router

# 路由註冊（加在路由註冊區塊）
app.include_router(
    user_router.router,
    prefix="/api/v1/users",
    tags=["users"]
)
=====================================================================
```

#### SQL 腳本格式

```sql
-- =====================================================================
--   建立使用者資料表
-- =====================================================================
-- 更新時間：2025-11-14
--
-- 用途說明：
-- 建立 users 資料表，用於儲存使用者帳號資訊
--
-- 使用方式：
-- 1. 在資料庫管理工具中開啟此檔案
-- 2. 連線到目標資料庫
-- 3. 執行此 SQL 腳本
--
-- 注意事項：
-- - 此範例適用於 PostgreSQL
-- - 如使用 MySQL，請調整資料類型
-- - 如使用 SQLite，請調整 AUTO_INCREMENT 語法
-- =====================================================================

-- 建立資料表
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    username VARCHAR(50) NOT NULL UNIQUE,
    email VARCHAR(100) NOT NULL UNIQUE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 建立索引
CREATE INDEX idx_users_username ON users(username);

-- =====================================================================
```

## 工作流程

### 標準流程

```
1. Claude 產生檔案到 shopfloor/Claude_TMP/
   ↓
2. Claude 在對話中簡要說明：
   - 本次產生的檔案清單
   - 使用順序
   - 注意事項
   ↓
3. 使用者在 IDE 開啟檔案
   ↓
4. 使用者根據檔案開頭的說明進行操作：
   - SQL 腳本 → 在資料庫工具執行
   - 完整檔案 → 加入專案對應目錄
   - 部分代碼 → 複製到目標位置
   - 配置檔案 → 放到專案根目錄或 config/ 目錄
   ↓
5. 使用者簡短回報結果：
   - "執行成功" / "建表完成"
   - "檔案已加入專案"
   - "報錯：[錯誤訊息]"
   - "需要調整：[具體需求]"
   ↓
6. Claude 根據回報繼續產生下一個檔案
```

## 例外情況

以下情況**可以直接使用 Write/Edit 工具修改專案檔案**：

### ✅ 允許直接修改的情況

**1. 緊急 Bug 修正**
- 編譯錯誤修正（少於 10 行）
- 語法錯誤修正
- 明顯的 Typo 修正

**2. 配置檔微調**
- 環境變數調整
- 連線字串修改（不含敏感資訊）
- 簡單的配置參數

**3. 小幅度調整**
- 單一變數名稱修改
- 單一函式參數調整
- 註解補充（少於 5 行）

**4. 使用者明確要求**
- 使用者說「請直接改」
- 使用者說「不用產生檔案，直接修正」

### ❌ 禁止直接修改的情況

**1. 新功能開發**
- 新增類別、函式、模組
- 新增資料表、欄位
- 新增 UI 元件或頁面

**2. 大幅度重構**
- 架構調整
- 介面重新設計
- 業務邏輯重寫
- 超過 20 行的修改

**3. 不確定的修改**
- 需要使用者確認的變更
- 有多種實作方式的情況
- 可能影響其他模組的修改

## 違反規範的處理

### 自我檢查清單

在執行工具前，先問自己：

- [ ] 這個修改是否超過 20 行？
- [ ] 這個修改是否是新功能或大幅重構？
- [ ] 使用者是否需要先確認這個修改？
- [ ] 這個修改是否可能影響其他模組？

如果**任何一項回答「是」**，就應該：
1. 先產生檔案到 `shopfloor/Claude_TMP/`
2. 在對話中簡要說明
3. 等待使用者確認
