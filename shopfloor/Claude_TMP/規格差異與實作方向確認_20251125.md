# 費用申請單 (ExpenseClaimForm) 規格與現況差異確認

日期：2025-11-25
對象：專案負責人

經過詳細比對您的最新規格需求（`shopfloor/費用申請單規格TMP/費用申請單規格.txt`）與目前程式碼（`shopfloor/Claude_TMP/dNet/ExpenseClaimForm.aspx`），發現兩者在「資料結構」與「表單邏輯」上有根本性的差異。

為了確保開發方向正確，請您確認以下重大差異與建議調整方向：

## 1. 核心結構差異（最關鍵）

| 項目 | 最新規格要求 (`費用申請單規格.txt`) | 目前程式碼現況 (`ExpenseClaimForm.aspx`) | 差異分析 |
| :--- | :--- | :--- | :--- |
| **單據邏輯** | **單一供應商，多項商品/費用**<br>標準 SAP AP Invoice 結構。<br>表頭決定供應商，明細列是該供應商的商品/費用項目。 | **多張發票/多供應商？**<br>明細列包含 `U_LIFNR` (供應商)、`U_XBLNR` (發票號碼)。<br>看起來像是「發票登錄清單」或「進項稅額明細表」。 | **結構完全不同**。<br>目前的 Grid 每一列都是一張獨立的發票(含供應商)，但規格要求 Grid 每一列是同一張發票的明細項目。 |
| **表頭欄位** | **豐富的單據資訊**<br>供應商代碼/名稱、發票號碼、幣別、收貨地址、日期(文件/過帳/到期)、付款條件等。 | **極簡資訊**<br>ID, DocEntry, DocNum, 總計, 稅額, 建立人/時。 | 缺乏規格指定的大部分欄位（如供應商、日期控制項、地址等）。 |
| **明細欄位** | **商品/費用項目**<br>項目代碼 (ItemCode)、說明、數量、單價、稅碼、科目。 | **發票稅務資訊**<br>發票號碼、發票類型(21/25..)、稅額、未稅金額、營業稅日期。 | 目前的欄位是針對「稅務申報 (GUI/VAT)」設計的，而非「費用/商品採購」明細。 |

## 2. UI/UX 互動功能差異

*   **搜尋功能**：
    *   **規格**：要求文字框可編輯 + 側邊搜尋按鈕 + 下拉選單（模糊/開始於/完全比對/結束於）。
    *   **現況**：尚未實作此進階搜尋 UI。
*   **驗證機制**：
    *   **規格**：
        1.  欄位下方隱藏錯誤訊息區塊。
        2.  離開欄位(OnBlur)即時驗證。
        3.  阻擋儲存/送出。
    *   **現況**：僅有簡單的 `ValidateMasterFields` (尚未完整實作) 和頂部統一的 `lblMessage`。
*   **地址連動**：
    *   **規格**：需新增 `jtdb.addr` 資料表，並實作下拉選單選擇地址後自動帶入。
    *   **現況**：尚未實作。

## 3. 建議調整方向

鑑於上述差異，目前的 `ExpenseClaimForm.aspx` 似乎是基於早期或不同的需求（可能是批次發票輸入或稅務調節表）開發的。

**若要符合您最新的「費用申請單規格.txt」，我建議採取以下行動：**

1.  **重構表單邏輯 (Rewrite)**：
    *   捨棄目前 Grid 中「每一列都是不同供應商發票」的邏輯。
    *   **表頭**：新增供應商、日期、地址等欄位。
    *   **明細**：將欄位改為 ItemCode, Dscription, Quantity, Price, AcctCode 等。
2.  **資料庫/後端調整**：
    *   目前的寫入邏輯是 `INSERT INTO MGUIAP_Import` (看起來是進項稅額匯入檔)。
    *   是否確認此表單最終目的是建立 SAP 的 **AP Invoice (OPCH)**？如果是，目前的寫入邏輯需要調整為符合 AP Invoice 的結構（Header + Lines）。
3.  **優先實作 UI 框架**：
    *   先依據新規格建立 UI (Header/Grid/Footer)。
    *   實作您要求的「搜尋按鈕組合控制項」與「錯誤訊息驗證機制」。
