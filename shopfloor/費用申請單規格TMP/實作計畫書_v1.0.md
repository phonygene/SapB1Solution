## 規格概述

### 核心變更

1. **介面重構**：從 MDR 發票明細單 → SAP B1 標準 AP Invoice 格式
2. **錯誤驗證**：實作即時欄位驗證與錯誤訊息顯示機制
3. **查詢子視窗**：實作可重用的查詢選擇視窗元件
4. **三層驗證**：SQL Injection 防護 → 資料型別/長度檢查 → 業務邏輯驗證

### 階段劃分

- **Phase 1（本次）**：介面調整 + 錯誤訊息欄位 + 資料型別/長度檢查
- **Phase 2（後續）**：查詢子視窗物件實作
- **Phase 3（後續）**：業務邏輯驗證（發票號碼格式、供應商存在性等）

## 錯誤驗證機制

### 三層驗證架構

```
使用者輸入
    ↓
【第一層：SQL Injection 防護】
    ├─ 檢查特殊字元：'; --, /*, xp_, sp_
    ├─ 檢查 SQL 關鍵字：SELECT, INSERT, UPDATE, DELETE, DROP, EXEC
    ├─ 使用參數化查詢
    ↓
【第二層：資料型別與長度檢查】← 本次實作
    ├─ 檢查資料型別（string, int, decimal, date）
    ├─ 檢查字串長度（是否超過 MaxLength）
    ├─ 檢查數值範圍
    ├─ 檢查日期格式
    ↓
【第三層：業務邏輯驗證】← 後續實作
    ├─ 供應商代碼存在性檢查
    ├─ 發票號碼格式檢查
    ├─ 必填欄位檢查
    ├─ 欄位間關聯檢查
```

### 錯誤訊息顯示規則

#### 表頭/表尾欄位

**觸發時機**：當使用者離開欄位時（OnBlur、LostFocus）

**顯示位置**：欄位正下方

**HTML 結構**：
```html
<div class="form-row">
    <span class="form-label">供應商代碼:</span>
    <asp:TextBox ID="txtCardCode" runat="server" CssClass="form-input" MaxLength="15"></asp:TextBox>
    <span id="errCardCode" class="error-hint" style="display:none;"></span>
</div>
```

**CSS 樣式**：
```css
.error-hint {
    color: #D32F2F;
    font-size: 12px;
    margin-top: 2px;
    display: block;
}
```

#### 明細欄位

**觸發時機**：
- 使用者選擇本列以外的欄位
- 新增一列新列，自動選擇新列第一欄
- 改為選擇了之前編輯的列的欄位
- 改為選擇表頭或表尾的欄位
- 按下表單的新增按鈕

**顯示位置**：明細區域上方（所有明細共用）

**HTML 結構**：
```html
<div class="section">
    <div class="section-header">發票明細</div>
    <!-- 明細共用錯誤訊息區域 -->
    <div id="divDetailError" class="detail-error-container" style="display:none;">
        <span id="lblDetailError" class="error-message"></span>
    </div>
    <div class="section-body">
        <asp:GridView ID="gvInvoiceDetail" ...>
        </asp:GridView>
    </div>
</div>
```

### 儲存按鈕控制

**規則**：當頁面有任何錯誤訊息顯示時，不允許使用者執行新增或更新表單。

**實作方式**：
```vb
Private Function HasAnyErrors() As Boolean
    ' 檢查所有表頭/表尾錯誤訊息
    If errCardCode.Style("display") <> "none" Then Return True
    If errCardName.Style("display") <> "none" Then Return True
    ' ... 其他欄位

    ' 檢查明細錯誤訊息
    If divDetailError.Style("display") <> "none" Then Return True

    Return False
End Function

Protected Sub btnSave_Click(sender As Object, e As EventArgs)
    If HasAnyErrors() Then
        ShowMessage("請先修正所有錯誤後再儲存")
        Return
    End If

    ' 繼續儲存邏輯...
End Sub
```

## 查詢子視窗物件

### 規格定義

**觸發方式**：使用者在特定欄位按下 Tab 鍵

**視窗功能**：
1. 顯示 SQL 查詢結果（GridView）
2. 頂部有搜尋欄位
3. 欄位標題可雙擊選擇作為搜尋目標
4. 預設以第一個欄位搜尋
5. 支援萬用字元 `*`（前置/包含模式）

### 查詢規則

**前置模式（無 `*`）**：
```sql
WHERE CardCode LIKE '{輸入值}%'
```

**包含模式（有 `*`）**：
```sql
WHERE CardCode LIKE '%{移除*後的輸入值}%'
```

### 實作方式（建議）

**方案 A：Modal Popup（推薦）**
- 使用 AJAX Control Toolkit 的 ModalPopupExtender
- 優點：不離開當前頁面，UX 較好
- 缺點：需要引入 AjaxControlToolkit

**方案 B：新視窗**
- 使用 `window.open()` 開啟新視窗
- 優點：實作簡單
- 缺點：使用者體驗較差

**方案 C：UserControl**
- 建立可重用的 UserControl
- 優點：程式碼重用性高
- 缺點：初期開發成本較高

**建議**：採用方案 A（Modal Popup），並建立可重用的 ChooseFromList UserControl

### 需要的查詢類型

| 觸發欄位 | 查詢目標 | SQL |
|---------|---------|-----|
| 供應商代碼 | OCRD | `SELECT CardCode, CardName FROM OCRD WHERE CardType='S' AND FrozenFor='N'` |
| 供應商名稱 | OCRD | 同上 |
| 項目號碼 | OITM | `SELECT ItemCode, ItemName FROM OITM WHERE FrozenFor='N'` |
| 項目說明 | OITM | 同上 |
| 總帳科目 | OACT | `SELECT AcctCode, AcctName FROM OACT WHERE FrozenFor='N'` |

### 新增本機資料表：addr（收貨地址）

**目的**：儲存常用的收貨地址清單

**資料表結構**：

```sql
CREATE TABLE [dbo].[addr] (
    [ID] INT IDENTITY(1,1) PRIMARY KEY,
    [addrType] CHAR(1) NOT NULL DEFAULT 'R',  -- D=交貨, R=收貨
    [addrName] NVARCHAR(50) NOT NULL,         -- 地址名稱
    [address] NVARCHAR(254) NOT NULL,         -- 地址
    [active] CHAR(1) NOT NULL DEFAULT 'Y',    -- Y=啟用, N=停用
    [createDate] DATETIME DEFAULT GETDATE(),
    [updateDate] DATETIME DEFAULT GETDATE(),
    CONSTRAINT CK_addr_addrType CHECK (addrType IN ('D', 'R')),
    CONSTRAINT CK_addr_active CHECK (active IN ('Y', 'N'))
)

-- 建立索引
CREATE INDEX IX_addr_addrType ON addr(addrType)
CREATE INDEX IX_addr_active ON addr(active)
```
