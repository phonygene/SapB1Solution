# 整合任務 (Super Agent)

整合所有 Agent 的成果，智能合併代碼。

## 參數

```
/integrate {task-id}
```

- `task-id`：要整合的藍圖任務 ID

## 執行步驟

### 1. 檢查前置條件

讀取 `.agent-workspace/blueprints/{task-id}.md`，確認：
- 所有 Agent 狀態都是 `completed`
- 如果有 Agent 未完成，列出並詢問是否繼續

### 2. 收集變更資訊

從 git log 找出所有相關 commit：

```bash
git log --oneline --grep="{task-id}"
```

列出每個 Agent 的變更：
- Commit hash
- 修改的檔案
- 變更摘要

### 3. 檢查是否有副本需要整合

查看藍圖的「副本追蹤」區塊和 `.agent-workspace/working/` 目錄

### 4. 整合策略

#### 情況 A：無副本（所有 Agent 直接修改主代碼）

1. 檢查是否有衝突（同一檔案被多個 Agent 修改）
2. 如果無衝突，任務已完成
3. 如果有衝突，進行智能合併（見下方）

#### 情況 B：有副本（需要合併副本到主代碼）

1. 讀取每個副本的內容
2. 讀取主代碼的當前內容
3. 分析每個副本相對於原始版本的變更
4. 智能合併到主代碼

### 5. 智能合併

這是 AI 取代傳統 Git Merge 的核心價值：

1. **理解意圖**：讀取藍圖中每個 Agent 的任務摘要，理解每個變更的目的

2. **分析變更**：
   - 哪些是新增的代碼？
   - 哪些是修改的代碼？
   - 哪些可能有邏輯衝突？

3. **合併策略**：
   - 不同區塊的變更 → 直接合併
   - 同一區塊的變更 → 理解意圖後重構整合
   - 邏輯衝突 → 詢問用戶決定

4. **品質檢查**：
   - 合併後的代碼是否符合 CLAUDE.md 原則
   - 是否有語法錯誤
   - 是否有明顯的邏輯問題

### 6. 更新主代碼

將整合後的代碼寫入主代碼檔案

### 7. Commit 整合結果

```bash
git add .
git commit -m "[integrate] {task-id}: 整合 {N} 個 Agent 的成果"
```

### 8. 清理副本

如果整合成功：
1. 刪除 `.agent-workspace/working/*/{ task-id}/` 目錄
2. 更新藍圖狀態為 `completed`

### 9. 回報整合結果

```
整合完成：{task-id}

整合的 Agent：
- A1 (backend): {摘要}
- A2 (ui-ux): {摘要}

合併處理：
- {檔案}: {處理方式}

最終 Commit: {commit hash}

驗收標準檢查：
- [x] {標準1}
- [x] {標準2}
```

## 整合原則

### 優先順序

當有衝突時，按以下順序考慮：

1. **藍圖中定義的整合順序**
2. **Backend 優先於 UI**（資料層先於展示層）
3. **最後修改的版本**（如果邏輯上合理）

### 可以自動處理

- 不同函數/方法的新增
- 不同區塊的 CSS 樣式
- 不同控制項的事件處理
- Import/Using 語句的合併

### 需要詢問用戶

- 同一函數內的邏輯變更
- 互相依賴的變更
- 可能影響業務邏輯正確性的變更

## 注意事項

- 整合前先備份（git stash 或建立分支）
- 如果整合太複雜，可以分階段進行
- 整合後建議進行功能測試
- 保留整合過程的 commit 記錄，便於追溯
