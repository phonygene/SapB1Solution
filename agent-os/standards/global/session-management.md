## 工作階段管理規範 (Session Management Standards)

### 工作階段指令

#### Session On 指令
**觸發**: 當使用者說 "Claude, sess on."

**動作**:
1. 讀取 `worklog/LastCheckPoint.log` 檔案
2. 檢視最新的專案狀態與待辦事項
3. 向使用者報告：
   - 上次工作的時間點
   - 當前專案狀態摘要
   - 未完成的待辦事項
   - 建議的下一步工作
4. 準備好接續上次的工作進度

**用途**: 上班/開始工作

#### Session Check 指令
**觸發**: 當使用者說 "Claude, sess check."

**動作**:
1. **僅報告**當前工作進度，不寫入任何檔案
2. 口頭彙整以下內容：
   - 本次階段已完成的任務
   - 進行中的任務及其狀態
   - 遇到的問題
   - 待辦事項清單
3. 供使用者確認進度，不產生記錄檔案

**用途**: 快速確認當前狀態，不改變記錄

#### Session Wrap 指令
**觸發**: 當使用者說 "Claude, sess wrap."

**動作**:
1. 彙整本次工作階段的內容（同 Session Off）：
   - 完成的任務清單
   - 進行中但未完成的任務
   - 遇到的問題與解決方案
   - 重要的決策記錄
   - 程式碼變更摘要
2. 建立新的歷史記錄檔案：
   - 路徑：`worklog/checkPoint_YYYYMMDD_HHMM.log`
   - 格式：詳細的工作記錄，包含時間戳記與完整細節
3. 更新最新狀態檔案：
   - 路徑：`worklog/LastCheckPoint.log`
   - 內容：最新的專案狀態快照、待辦清單、下次啟動建議
4. 向使用者提供彙整報告
5. **繼續工作**，不結束對話

**用途**: 階段性存檔記錄，但不下班

#### Session Off 指令
**觸發**: 當使用者說 "Claude, sess off."

**動作**:
1. 執行與 Session Wrap 相同的彙整與記錄動作（步驟 1-4）
2. 向使用者道別，**結束工作階段**

**用途**: 完整存檔並下班

### 工作記錄檔案結構

#### checkPoint_YYYYMMDD_HHMM.log（歷史記錄）
```
=== 工作階段記錄 ===
時間：YYYY-MM-DD HH:mm - HH:mm
專案：[專案名稱]

## 完成的任務
- [任務1]: [詳細說明]
- [任務2]: [詳細說明]

## 進行中的任務
- [任務3]: [當前狀態與阻礙]

## 重要決策
- [決策1]: [理由與影響]

## 程式碼變更
- [檔案路徑]: [變更內容]

## 遇到的問題
- [問題描述]: [解決方案或待解決]

## 下次待辦
- [ ] [待辦事項1]
- [ ] [待辦事項2]
```

#### LastCheckPoint.log（最新狀態）
```
=== 最新工作狀態 ===
最後更新：YYYY-MM-DD HH:mm

## 專案狀態
[當前專案的整體狀態描述]

## 待辦事項
- [ ] [高優先權任務]
- [ ] [中優先權任務]
- [ ] [低優先權任務]

## 下次啟動建議
[建議從哪裡開始繼續工作]

## 重要提醒
[需要特別注意的事項]
```

### 檔案管理規則

- **worklog 目錄**: 所有工作記錄統一存放於專案根目錄的 `worklog/` 資料夾
- **自動建立**: 如果 `worklog/` 目錄不存在，自動建立
- **歷史保留**: 所有 `checkPoint_*.log` 檔案永久保留，用於追溯歷史
- **狀態同步**: 每次 clock out 時同時更新兩個檔案

### 工作連續性保證

- **狀態恢復**: Clock in 時能完整恢復上次的工作情境
- **進度追蹤**: 清楚記錄每個任務的完成度
- **知識傳承**: 詳細記錄決策理由，避免重複討論
- **問題追蹤**: 記錄未解決的問題，確保不遺漏
