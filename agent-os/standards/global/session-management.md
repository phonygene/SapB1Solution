## 工作記錄規範 (Worklog Standards)

> 取代原有的 Session 彙整機制，改為即時記錄

---

## 核心原則

**每次請求後即時記錄，不做集中彙整**

優點：
- 分散記錄比集中彙整更省 Token
- 即時記錄不遺漏
- Git 管理可追溯
- 不需要 sess-wrap/sess-off 等指令

---

## 記錄檔案結構

```
worklog/
├── WORKLOG.md      # 即時工作記錄
├── DECISIONS.md    # 重要決策記錄
└── ISSUES.md       # 問題追蹤
```

### WORKLOG.md - 即時工作記錄

**記錄時機**：每次完成用戶請求後

**格式**：
```markdown
### HH:MM - 簡短標題
- 要求：用戶要求的內容
- 結果：執行結果摘要
- 檔案：涉及的檔案
- 問題：（如有）遇到的問題
```

**原則**：精簡，每次 2-5 行即可

### DECISIONS.md - 重要決策記錄

**記錄時機**：做出重要技術決策或達成共識時

**格式**：
```markdown
### 決策標題
- **決策**：具體決策內容
- **原因**：為什麼做這個決策
- **日期**：YYYY-MM-DD
```

**用途**：避免重複討論已決定的事項

### ISSUES.md - 問題追蹤

**記錄時機**：遇到問題或 Bug 時

**格式**：
```markdown
### [狀態] 問題標題
- **描述**：問題描述
- **解決**：（如已解決）解決方案
- **狀態**：待解決 / 已解決
```

---

## 工作流程

```
1. 用戶提出請求
   ↓
2. Claude 執行請求
   ↓
3. 完成後追加記錄到 WORKLOG.md（2-5 行）
   ↓
4. 如有重要決策 → 記錄到 DECISIONS.md
   ↓
5. 如遇到問題 → 記錄到 ISSUES.md
   ↓
6. 詢問用戶是否 commit
```

## 已棄用的指令

以下 Session 指令已棄用，改為即時記錄：

- ~~sess on~~ → 直接開始工作，查看 WORKLOG.md 了解上次進度
- ~~sess check~~ → 查看 WORKLOG.md 和 ISSUES.md
- ~~sess wrap~~ → 不再需要，已即時記錄
- ~~sess off~~ → 不再需要，已即時記錄
